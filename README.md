# Модуль оплаты ХуткiГрош (ЕРИП) для OpenCart

Модуль обеспечивает взаимодействие интернет-магазина на базе **OpenCart** с платёжным сервисом [ХуткiГрош](https://hutkigrosh.by): выставление счетов в ЕРИП (АИС "Расчет"), оплата картой (WebPay), QR-код, автоматическое обновление статусов заказов после оплаты.

## Поддерживаемые версии

Поддерживаются одновременно две версии модуля:

| | [Hutkigrosh API v3](#настройка-hutkigrosh-api-v3) (рекомендуется) | [Hutkigrosh](#настройка-hutkigrosh-предыдущее-поколение) (предыдущее поколение) |
|---|---|---|
| Текущая версия | 3.0.0 (3.x) / 3.0.1-oc4 (4.x) | 2.0.0 (3.x) / 2.0.4-oc4 (4.x) |
| API | актуальное поколение (REST API v3) | предыдущее поколение API |

| Тестовая система | api-sandbox.hgrosh.by | trial.hgrosh.by |
| Кому подходит | новым магазинам и тем, кто переходит на API v3 | действующим магазинам, работает как раньше |

> Сервис ХуткiГрош сейчас поддерживает все поколения API параллельно.

Следите за анонсами о сроках отключения старого API и переходите на API v3 заранее (порядок перехода описан в разделе "[Одновременная работа и переход на API v3](#одновременная-работа-и-переход-на-api-v3)").

## Требования

- PHP 5.6 и выше (для OpenCart 4 требуется PHP 8.0 и выше, как требует сама CMS), расширение [cURL](https://www.php.net/manual/ru/book.curl.php)

## Установка (одинакова для обеих версий модуля)

**OpenCart 4.x:**

1. Создайте резервную копию магазина и базы данных.
1. Скачайте архив нужной сборки (раздел "Скачать").
1. В админке: **Расширения > Установщик**, загрузите архив и нажмите "Установить".
1. Перейдите: **Расширения > Расширения**, выберите тип фильтра **Оплата**, напротив модуля **HutkiGrosh API v3** (сборка API v3; для сборки предыдущего поколения — имя, заданное при её установке) нажмите "Установить", затем "Редактировать".

**OpenCart 2.x – 3.x:**

1. Создайте резервную копию магазина и базы данных.
1. Скачайте архив нужной сборки (раздел "Скачать").
1. В админке: **Модули > Установка расширений**, установите скачанный архив.
1. Перейдите: **Модули > Платежи**, напротив модуля **HutkiGrosh** нажмите "Установить", затем "Изменить".

## Настройка Hutkigrosh API v3

### Шаг 1. Получите API-токен

В бизнес-аккаунте ХуткiГрош откройте **Настройки > Интеграция ПУ** (раздел доступен ролям "Владелец ПУ" и "Администратор ПУ"). Используйте токен с доступом к информации о ПУ и созданию/редактированию счетов.

### Шаг 2. Подключите магазин

1. В настройках модуля вставьте токен в поле **API Токен**.
1. Нажмите кнопку "Загрузить данные" (в OpenCart 4.x: "Актуализировать"), модуль загрузит из ХуткiГрош списки для полей **Розничная торговая точка**, **Услуга**, **Кассовое место** (в OpenCart 4.x справочники кэшируются в настройках и восстанавливаются при открытии формы без обращения к API).
1. Выберите значения в списках и сохраните изменения.

### Шаг 3. Остальные параметры

**Основное:**
* **Статус**: включен/выключен способ оплаты (стандартное поле расширения).
* **Порядок сортировки**: позиция способа оплаты в списке при оформлении заказа.
* **Путь в дереве ЕРИП**: путь, по которому клиент будет искать выставленный счёт (например, `АИС "Расчет" (ЕРИП) > Интернет-магазины/сервисы >`).
* **Срок действия счета (дней)**: как долго счёт будет доступен в ЕРИП для оплаты.
* **Debug mode**: расширенное логирование в файл cmsgate.log (используется при диагностике).

**Экран успешного заказа:**
* **Секция "Инструкция"**: пошаговая инструкция по оплате счёта в ЕРИП.
* **Секция QR-код**: оплата счёта по QR-коду через мобильное приложение банка (QR-код и ссылка на оплату запрашиваются у сервиса).
* **Секция Webpay**: кнопка оплаты счёта картой (переход на Webpay).
* **Текст успешного выставления счета**: может содержать HTML, допустимы переменные `@order_id`, `@order_number`, `@order_total`, `@order_currency`, `@order_fullname`, `@order_phone`, `@order_address`.
* **CSS файл для итогового экрана**: путь к собственному CSS-файлу оформления.

**Статусы заказов** (выбор из существующих статусов магазина, в скобках рекомендуемое значение из стандартного набора OpenCart):
* **Статус при выставлении счета**: какой статус установить заказу после выставления счёта в ЕРИП. Рекомендуется "Ожидание" (Pending), заказ ожидает оплаты.
* **Статус при успешной оплате счета**. Рекомендуется "Обработан" (Processed), оплата получена, заказ ожидает комплектации и отправки.
* **Статус при отмене оплаты счета**. Рекомендуется "Отменён" (Canceled).
* **Статус при ошибке оплаты счета**. Рекомендуется "Неудачный платёж" (Failed).

**Уведомления** (отправляются шлюзом ХуткiГрош):
* **Email оповещение**: письмо клиенту при успешном выставлении счёта.
* **Sms оповещение**: SMS клиенту при успешном выставлении счёта.

**Способ оплаты для клиента:**
* **Название способа оплаты** и **Описание способа оплаты** - название и описание способа оплаты отображаемое пользователю, рекомендуется для заполнения в зависимости от шаблона `Через систему 'Расчет' (ЕРИП)`.

### Обязательно: адрес обработчика уведомлений

Для автоматического обновления статуса заказа (после оплаты клиентом счёта в ЕРИП) сообщите в службу технической поддержки ХуткiГрош адрес обработчика, указав Ваш домен:

* для OpenCart 4.x
    ```
    https://ваш-домен/index.php?route=extension/cmsgate_opencart_hutkigrosh/payment/hutkigrosh.notify
    ```
* для OpenCart 2.3 – 3.x
    ```
    https://ваш-домен/index.php?route=extension/payment/hutkigrosh/notify
    ```
* для OpenCart 2.1
    ```
    https://ваш-домен/index.php?route=payment/hutkigrosh/notify
    ```

Модуль принимает уведомление GET-запросом с идентификатором счёта (`purchaseid`) в URL.

### Тестовый режим (Sandbox)

1. Получите API-токен тестовой системы (выдаётся при регистрации в ХуткiГрош).
1. Включите в настройках модуля режим Sandbox.
1. Счета будут выставляться в тестовую систему `api-sandbox.hgrosh.by`.
1. Для эмуляции оплаты счёта используйте [личный кабинет](https://cabinet.hgrosh.by) (сверху-справа "Профиль пользователя" > "Тестовый режим").

Документация API v3: https://api-dev.hgrosh.by/eripservice/docs/ru/index.html

## Одновременная работа и переход на API v3

* Обе сборки являются одним и тем же расширением (общий код и общая группа настроек): сборка API v3 устанавливается **поверх** предыдущей версии и замещает её файлы; заказы и данные магазина не затрагиваются. Обратный переход выполняется установкой предыдущей сборки поверх.
* Адрес обработчика уведомлений **не меняется**: сообщать в поддержку ХуткiГрош новый адрес не нужно.
* Способ оплаты в магазине остается один: двойная обработка уведомлений исключена.
* Настройки статусов, текстов и секций сохраняются при переходе; поля подключения меняются: вместо "Логин/Пароль/ЕРИП ID/Код услуги" заполняется "API Токен" и справочники (ранее сохраненные значения остаются в базе данных).

Рекомендуемый порядок перехода:

1. Создайте резервную копию магазина и базы данных.
1. Получите API-токен тестовой системы (см. "Настройка Hutkigrosh API v3", шаг 1).
1. Установите сборку API v3 поверх предыдущей версии (порядок установки см. в разделе "Установка").
1. В настройках модуля вставьте токен в поле "API Токен", нажмите "Загрузить данные" ("Актуализировать") и выберите значения в списках "Услуга", "Розничная торговая точка", "Кассовое место".
1. Включите режим Sandbox и проверьте выставление и оплату счёта (эмуляция оплаты в личном кабинете тестовой системы, см. "Тестовый режим").
1. Выключите Sandbox: счета будут выставляться в рабочую систему.
1. Проверьте обработчик уведомлений: статус заказа в магазине должен измениться после оплаты счёта.

## Логи

Модуль ведет лог файл по пути (для обоих поколений API одинаковому):

* OpenCart 4.x:
`<корень_сайта>/extension/cmsgate_opencart_hutkigrosh/system/library/esas/cmsgate/hutkigrosh/vendor/esas/cmsgate-core/logs/cmsgate.log`
* OpenCart 2.x – 3.x:
`<корень_сайта>/system/library/esas/cmsgate/hutkigrosh/vendor/esas/cmsgate-core/logs/cmsgate.log`

Для обеспечения **безопасности** необходимо убедиться, что в настройках http-сервера включена директива `AllowOverride All` для корневой папки.

## История изменений

* 3.0.1-oc4 (API v3, OpenCart 4.x): имя модуля в списке расширений OpenCart 4 (Расширения > Оплата) изменено на «HutkiGrosh API v3»: обновлены `heading_title` в админ-локализациях (ru/be/en) и `name` в `install.json`. Имя применяется после обновления файлов расширения (переустановка из новой сборки).
* 2.0.4-oc4 (API v1, OpenCart 4.x; пересборка без смены версии): имя модуля в списке расширений изменено на «ХуткиГрош (ЕРИП)»: обновлены `heading_title` в админ-локализациях (ru/be/en), `name` в `install.json` упрощено до «ХуткиГрош (ЕРИП)».
* 3.0.0-oc4 (API v3, OpenCart 4.x): переход на API v3 сервиса ХуткiГрош: API-токен, справочники "Услуга/Розничная торговая точка/Кассовое место" с кэшированием и кнопкой "Актуализировать", QR-код и ссылка на оплату из API, уникальный номер счёта при коллизии. Проверено на тестовом sandbox (OpenCart 4.1.0.4).

## Инструкция по сборке

* возьмите уже собранный файл из папки соответствующей версии OpenCart (v2, v3, v4)
* при сборке cmsgate_opencart_hutkigrosh.ocmod.zip (для OpenCart 4.x) необходимо:
    * архивировать содержимое каталога `upload/`
    * удалить каталоги
        * `admin/controller/extension/payment`
        * `admin/view/template/extension/payment`
        * `catalog/controller/extension/payment`
        * `catalog/model/extension/payment`
        * `catalog/view/theme/default/template/extension/payment`
* при сборке cmsgate-opencart-hutkigrosh.ocmod.zip (для OpenCart 2.3) необходимо удалить каталоги
    * `upload/admin/controller/payment`
    * `upload/admin/view/template/payment`
    * `upload/catalog/controller/payment`
    * `upload/catalog/model/payment`
    * `upload/catalog/view/theme/payment`
* при сборке cmsgate-opencart21-hutkigrosh.ocmod.zip (для OpenCart 2.1) необходимо удалить каталоги
    * `upload/admin/controller/extension/payment`
    * `upload/admin/view/template/extension/payment`
    * `upload/catalog/controller/extension/payment`
    * `upload/catalog/model/extension/payment`
    * `upload/catalog/view/theme/default/template/extension/payment`

### Сборка плагина

```
> composer global require humbug/php-scoper
> php-scoper add-prefix
> composer dump-autoload --working-dir build --classmap-authoritative
```
